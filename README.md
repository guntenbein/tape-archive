# tape-archive

Разбор длинных оцифровок кассет: конвейер слушает записи вместо вас и делает
каталог с таймкодами — где песни, где разговоры, где настройка инструмента,
что доиграно до конца, что оборвано, что технически уцелело и какую вещь
играют в архиве несколько раз.

Задача, под которую это писалось: десятки часов домашних плёнок 1980–2000
годов, которые жалко выбросить и невозможно переслушать.

На выходе — HTML-отчёт с плеером и структурированный JSON по каждой стадии.
Всё работает локально: ни звук, ни расшифровки никуда не отправляются.

> requests не отслеживаются, обратная совместимость не обещается.

## Что он делает

**Находит границы по смыслу,** а не режет каждые N минут: песня, разговор,
настройка, следующий дубль.

**Раскладывает по категориям** — музыка (целиком / оборвана / обрывок),
репетиция (играют и тут же разбирают), разговор, настройка инструмента,
аплодисменты, шум, тишина.

**Расшифровывает речь и вокал** с таймкодами, локально, через faster-whisper.

**Ищет одну и ту же вещь по всему архиву** — с поправкой на другую
тональность и другой темп. Это не фингерпринт: в репетиции одну песню играют
то выше, то быстрее, то с ошибками.

**Оценивает сохранность:** клиппинг, сетевой гул, шипение, провалы уровня,
полоса частот, ровность — и говорит, что из этого вернёт реставрация, а что
потеряно навсегда.

**Вытаскивает даты, названные вслух.** Люди часто проговаривают дату перед
записью; это надёжнее имени файла.

**Сортирует по приоритету A/B/C/D** с разбором, из чего сложилась оценка.

## Быстрый старт

```bash
./setup.sh                              # ffmpeg, venv, зависимости
./bin/tapearch ingest /путь/к/*.mp3     # положить оригиналы (режим 0444)
./bin/tapearch analyze                  # весь конвейер
./bin/tapearch serve                    # отчёт на 127.0.0.1:8765
```

Отчёт отдаётся только на localhost. С другой машины — через туннель:

```bash
ssh -L 8765:127.0.0.1:8765 <хост> 'cd ~/tape-archive && ./bin/tapearch serve'
```

`make selftest` прогоняет весь конвейер на синтетической ленте с заранее
известной разметкой и проверяет 22 свойства результата.

## Требования

Python 3.12, ffmpeg, sox, chromaprint. GPU не нужен: всё считается на CPU.
На 8 ядрах обработка идёт примерно **0.35× от длительности записи** — шесть
часов звука за два часа. Расшифровка речи — самая дорогая стадия.

Модели качаются сами при первом запуске: Whisper large-v3-turbo (~1.6 ГБ) и
PANNs CNN14 (~320 МБ). Без PANNs конвейер работает, но хуже различает речь и
музыку.

## Стадии

| стадия | что делает |
|---|---|
| `probe` | техпаспорт: кодек, LUFS, пики, полный скан клиппинга, шумовая полка, гул, шипение, полоса, стерео |
| `features` | покадровые признаки, две сетки: 23 мс для решений и 93 мс для хромы |
| `tags` | теги AudioSet по окнам 2 с (PANNs CNN14): речь, пение, музыка, хлопки |
| `segment` | правдоподобие пяти состояний → Viterbi → притяжение границ к паузам → разделение дублей |
| `classify` | категория сегмента и его признаки |
| `music` | законченность, провалы, качество, план реставрации |
| `transcribe` | расшифровка с таймкодами (faster-whisper, int8) |
| `cluster` | одна и та же вещь в разных местах архива |
| `rank` | оценка A/B/C/D с разбором по слагаемым |
| `report` | HTML с плеером, формой волны и пометками |

Подробно о том, почему стадии устроены именно так и на чём ломались прежние
версии — [docs/LESSONS.md](docs/LESSONS.md).

## Повторные запуски

У каждой стадии рядом с результатом лежит `<стадия>.done.json` с хэшем входа:
sha256 оригинала + версия параметров + маркеры зависимостей. Совпал — стадия
пропускается. Поменяли порог в `tapearch/config.py` и подняли версию стадии в
`STAGE_PARAMS_VERSION` — пересчитается только она и то, что от неё зависит.
Ctrl-C безопасен: следующий запуск продолжит с места.

```bash
./bin/tapearch analyze --only <слаг>     # одна лента
./bin/tapearch analyze --from segment    # пересчитать с сегментации
./bin/tapearch analyze --no-asr          # без расшифровки (вчетверо быстрее)
./bin/tapearch status                    # что уже посчитано
./bin/tapearch extract --grades A        # вырезать сегменты без перекодирования
```

## Раскладка данных

Корень задаётся переменной `TAPEARCH_DATA` или флагом `--data-root`,
по умолчанию `~/audio-archive`:

```
originals/        оригиналы, режим 0444, не изменяются никогда
manifest.json     имя, размер, sha256
work/<слаг>/      probe/features/segments/classify/music/transcript/rank + маркеры
derived/<слаг>/   preview.m4a для плеера
collection/       clusters.json, index.json
report/           index.html, <слаг>.html, songs.html
logs/             run-*.jsonl: тайминги и события стадий
```

Модели — в `~/.cache/tapearch-models` (переопределяется `TAPEARCH_MODELS`),
отдельно от данных, чтобы не качаться заново при смене корня.

## Реставрация

`tools/restore_a.py` обрабатывает музыкальные сегменты с оценкой A,
`tools/restore_talk.py` — разговорные блоки. Оригиналы не изменяются, всё
пишется в `restored/<слаг>/`.

Параметры у каждого сегмента свои и берутся из измерений: срез верха по
частоте, где сигнал перестаёт возвышаться над шумом; профиль шума — с
ближайшей паузы; notch и declip по фактическому гулу и клиппингу. Порядок —
declip до denoise, иначе шумодав примет срезанные вершины за сигнал.

Общую настройку применять нельзя: на проверенном архиве срез верха разошёлся
от 4 до 16 кГц. Разница между 4 и 16 — это разница между «срезал половину
музыки» и «оставил всё шипение».

## Чего он не делает

Не оценивает музыку. Оценивается сохранность и полезность материала, а не
исполнение.

Не чинит клиппинг до конца. Declip дорисовывает срезанные вершины
правдоподобно, но это реконструкция: при 10% и выше алгоритм уже сочиняет.

Не называет песни. Кластеры показывают, что вещь звучит несколько раз, но как
она называется — решает человек на слух, особенно когда расшифровка вокала
искажена.

Пороги оценок A/B/C/D откалиброваны по одному архиву и остаются условными.

## Google Drive

`tools/setup_gdrive.sh` проверяет настроенный remote rclone и выкачивает
папку. Скрипт ничего не создаёт и учётных данных не придумывает — настройка
remote на чтение остаётся за владельцем аккаунта. Два безопасных способа
описаны в [docs/GDRIVE.md](docs/GDRIVE.md).
